# Design

## Context

Watchlist хранит ручной порядок отдельно от Preferences. controller.setPreferences уже принимает
valid callback после своих асинхронных ожиданий и не перезагружает историю при изменении полей, не
относящихся к выбранному инструменту.

## Goals / Non-Goals

**Goals:** устойчивые отметки по UID, независимое хранение по профилю, одинаковая палитра в двух
точках входа.

**Non-Goals:** именованные пользовательские списки, публикация, смена поставщика данных, фон строки
и анимации цены.

## Decisions

- `watchlistFlags` — ограниченная карта стабильных ключей `uid:<uid>` / `legacy:<symbol>` и семи
  именованных цветов. `watchlistFlagFilter` — `all` либо имя цвета. Оба поля optional для
  совместимости старых backup.
- Валидатор принимает только обычные объекты или объекты без прототипа, не более 5000 записей, ключи
  до 200 символов с проверенным префиксом и алфавитом, цвета из enum.
- Все записи цветов и фильтра сериализуются по controller через WeakMap. Каждая операция читает
  актуальную карту после предыдущей записи и передаёт callback защиты owner/revision/import в
  setPreferences.
- Отдельный QuoteRow сохраняет файлы короче 500 строк. Флажок — отдельная кнопка внутри первой
  ячейки; события не доходят до выбора/удаления/переноса строки.
- Фильтр действует только на отображаемый массив, сохраняя исходные индексы строк для переноса.
  Камера и подписки остаются под управлением существующего controller.

## Risks / Trade-offs

- Одинаковый UID в нескольких строках → общий цвет по контракту инструмента.
- Асинхронный импорт либо замена карты извне → callback отклоняет устаревшую запись.
- Разные размеры окна → меню ограничивается реальной высотой и шириной окна; интеграционную
  визуальную проверку выполняет координатор.
