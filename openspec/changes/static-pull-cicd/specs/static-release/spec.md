# Spec Delta

## Purpose

Публиковать статическую оболочку терминала после проверенного слияния в main и давать оператору
возможность установить точное происхождение релиза и вернуть предыдущую исправную версию.

## ADDED Requirements

### Requirement: Проверенный источник релиза

Публикация SHALL использовать точный текущий SHA main только после успешного push CI этого SHA. PR
со сменой входов сборки SHALL повышать semantic version в package.json.

#### Scenario: CI ещё выполняется или завершился ошибкой

- **WHEN** main изменился, но соответствующий push CI не завершился успешно
- **THEN** текущая опубликованная версия остаётся доступной

#### Scenario: PR меняет приложение без повышения версии

- **WHEN** PR изменяет входы сборки и оставляет прежнюю package version
- **THEN** CI отклоняет PR до публикации

### Requirement: Привязка разовой публикации к проверенному SHA

При заданном MTP_DEPLOY_EXPECTED_SHA watcher SHALL принимать только полный lowercase SHA из 40 hex и
публиковать только этот SHA. Несовпадение текущего main SHALL останавливать запуск до CI query,
записи cooldown и сборки. Перед активацией выбранный SHA SHALL повторно сверяться с pin. Без
переменной SHALL сохраняться обычная публикация текущего проверенного main.

#### Scenario: Main продвинулся после внешней проверки

- **WHEN** оператор закрепил SHA A, но при запуске main указывает на зелёный SHA B
- **THEN** watcher завершается с ошибкой без CI query, install/build и изменения current

#### Scenario: Неверное значение pin

- **WHEN** задан пустой, сокращённый или иной некорректный SHA
- **THEN** watcher завершается с ошибкой до query и сборки

#### Scenario: Закреплённый SHA подтверждён

- **WHEN** main совпадает с pin и оба exact-SHA CI gates успешны
- **THEN** watcher публикует закреплённый SHA с обычной проверкой публичных файлов

### Requirement: Сборка на ограниченном сервере

Сервер SHALL самостоятельно получать исходники точного SHA и строить тот же статический payload
после успешных полных проверок hosted CI. Повторные lint, typecheck, тесты и проверка спецификаций
на VDS не требуются. До активации SHALL повторно подтверждаться текущий main и успешный CI того же
SHA.

#### Scenario: Проверенный SHA собирается на VDS

- **WHEN** hosted push CI текущего main SHA успешно завершил все обязательные проверки
- **THEN** VDS устанавливает зависимости по frozen lockfile и самостоятельно строит статические
  файлы
- **AND** version, buildId и hashes payload совпадают с полной сборкой тех же исходников

#### Scenario: CI изменился после сборки

- **WHEN** повторная проверка main или CI перед активацией не подтверждает исходный успешный SHA
- **THEN** собранный payload не активируется и прежний current сохраняется

#### Scenario: Ошибка установки или сборки

- **WHEN** frozen install или builder завершается ошибкой
- **THEN** current не переключается и автоматическая повторная попытка этого SHA блокируется до
  диагностики

### Requirement: Идентификация и проверка публикации

Релиз SHALL содержать только разрешённые статические файлы и публичную метаинформацию sourceSha,
version и buildId. Успех SHALL подтверждаться совпадением публичных файлов и контрольных сумм.

#### Scenario: Сервер или прокси выдаёт прежние файлы

- **WHEN** после переключения публичные файлы отличаются от целевого релиза
- **THEN** релиз не отмечается успешным и восстанавливается предыдущий указатель

### Requirement: Изоляция и восстановление

Публикация SHALL переключать только каталог этого сайта, сохранять предыдущий релиз и исключать
одновременные переключения. Откат SHALL приостанавливать автоматическую повторную публикацию.

#### Scenario: Ручной откат

- **WHEN** оператор выбирает сохранённый релиз
- **THEN** сайт переключается на него и watcher ждёт явного возобновления

### Requirement: Обновление установленного приложения

Публикация SHALL сохранять контракт PWA: свежий service-worker.js и version.json доступны без
длительного HTTP-кэша, а новый worker активируется по подтверждению пользователя после сохранения.

#### Scenario: Пользователь откладывает обновление

- **WHEN** новый worker готов, а пользователь выбирает обновить позже
- **THEN** открытая установленная оболочка продолжает работу до явного обновления
