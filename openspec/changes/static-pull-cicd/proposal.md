# Proposal

## Why

После слияния в main терминал должен публиковать проверенную статическую сборку без ручного
копирования. Нужны доказуемая версия, сохранение соседних сайтов и автоматический откат.

## What Changes

- GitHub CI проверяет PR и main; изменение входов сборки в PR требует повышения package version.
- Сервер опрашивает main, ждёт успешный CI точного SHA, собирает и атомарно переключает статику.
- Полные проверки остаются в hosted CI; VDS выполняет frozen install и тот же builder без повторного
  lint/typecheck/test/spec. Повторный exact-SHA CI gate перед активацией сохраняется.
- Публичный deployment.json связывает SHA, semantic version, content buildId и контрольные суммы.
- Health проверяет опубликованные файлы; ошибка возвращает предыдущий релиз.
- Optional SHA pin ограничивает reviewed разовую попытку конкретным SHA и закрывает гонку смены main
  между внешней проверкой оператора и запуском watcher.
- Инструкция описывает отдельный Linux systemd watcher, nginx, HTTPS и существующее PWA-обновление.

## Capabilities

### New Capabilities

- `static-release`: проверяемая публикация статической оболочки с откатом и идентификацией версии.

### Modified Capabilities

Нет.

## Impact

Новые workflow, deploy-скрипты, шаблоны systemd/nginx и инструкция. Runtime API, пользовательские
ключи и данные остаются на устройстве. Внешние runtime-зависимости не добавляются.
