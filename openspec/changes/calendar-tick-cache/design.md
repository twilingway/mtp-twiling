# Design

## Context

См. proposal.md: существующие части даты переиспользуются, выбранные деления — нет.

## Goals / Non-Goals

**Goals:** исключить повторный обход дат при неизменной X-проекции, сохраняя все команды paint.

**Non-Goals:** изменение алгоритма выбора делений, расчётов индикаторов, данных или поведения KLine.

## Decisions

1. Чистый CalendarAxisTicksCache хранит одну запись: временная ревизия, timeframe, identity display,
   точные from/to, CSS width, X начала целочисленного диапазона и знаковый шаг следующей позиции.
   Identity функции coordinate не используется; никакого округления или epsilon сравнения ключа.
   Аффинная X-проекция гарантирована Lightweight logicalToCoordinate. Невалидные координаты не
   кешируются. Исходный calendarAxisTicks остаётся неизменным эталоном.
2. Привязка lightweight-calendar.ts владеет кешем, display и ревизией на экземпляр. Любой setData и
   вставка новой временной позиции инвалидируют кеш. OHLC/volume update существующего timestamp
   сохраняет запись; замена timestamps внутри истории проходит через setData и инвалидирует её.
3. Обе ветви painter получают один readonly массив ticks. Высота, цвет, DPR, шрифт и размеры
   надписей применяются при каждом paint. Растры и canvas не кешируются, очистка canvas не мешает
   повторной отрисовке. При destroy единственная запись освобождается.
4. Полная привязка сетки и timeAxisPaneViews выделяется из lightweight.ts: это сокращает адаптер до
   лимита 500 строк и оставляет обработку календарных кадров у одного владельца.

## Validation

Проверить единичный расчёт для grid+axis и повторных Y-кадров при сохранении canvas-команд; промахи
после точных fractional X-изменений, ширины, истории, display и timeframe; отсутствие инвалидации от
OHLC/volume по прежнему timestamp. Сравнить результат с исходным алгоритмом для DST, Kathmandu,
D/W/M и будущих позиций. Сохранить существующие календарные проверки.

## Risks / Trade-offs

Ключ по одной длине или крайним timestamps пропустил бы замену внутри истории: требуется явная
ревизия setData. Y-жест может изменить ширину ценовой шкалы; width и реальные X входят в ключ и
вызывают корректный промах. Профиль CPU не доказывает выигрыш FPS: замер телефона остаётся отдельным
этапом координатора.

## Migration Plan

Узкие тесты и ревью, затем общую проверку и локальную интеграцию выполняет координатор. Откат
возвращает прямой вызов прежнего алгоритма без миграции пользовательских данных.
