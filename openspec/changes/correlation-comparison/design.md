# Design

## Context

Чистое ядро вычисляет коэффициент Пирсона по полному окну пар свечей. Список котировок хранит UID с
поставщиком и категорией. Несколько строк могут иметь одинаковый видимый тикер.

## Goals / Non-Goals

- Выбор конкретного UID из доступных инструментов, прогрев от 20 свечей по умолчанию и источник
  «Закрытие» по умолчанию.
- Один вычислительный и визуальный контракт для Lightweight Charts и KLineChart.

## Decisions

1. Поле выбора имеет явную подпись и элементы с тикером, названием и рынком. Значение — точный UID.
   Пустое значение открывает выбор и оставляет график индикатора без данных. Удалённый из списка UID
   сохраняется в настройках и отображается как недоступный.
2. `MarketClient.loadCandles` использует действующий клиент, выбранный профиль и права источника.
   Запрос запускается после выбора сохранённого инструмента. У основного графика сохраняются
   подписка, камера и свечи. Приложение не запрашивает дополнительные права доступа.
3. Ресурс привязан к клиентской сессии, UID основного и второго инструмента, интервалу и окну. При
   смене ключа запрос отменяется, поздний результат игнорируется. Сравнения, использующие один UID и
   интервал на графике, могут пользоваться общим чтением истории. Смена движка переиспользует ряд.
4. Сопоставление использует точные UTC метки начала свечей. Не совпавшие по времени свечи дают
   пропуски. Линия и заполнение имеют общую маску пропусков, границы −1, 0 и +1 настраиваются
   отдельно. Источник применяется к каждому ряду.
   [Формула и настройки](https://www.tradingview.com/support/solutions/43000502022-correlation-coefficient-cc/)

## Risks / Trade-offs

- Разные торговые расписания или временные сетки оставляют пропуски. Значение появляется после
  накопления заданного числа пар подряд.
- Длинное окно на обширной истории требует ограниченного расчёта. Терминал показывает состояние
  предела вычислений рядом с индикатором.

## Migration Plan

Новый идентификатор добавляется в действующую схему экземпляров. Предыдущие сохранения читаются по
своим идентификаторам. Клиент ранней версии запрашивает обновление перед применением снимка с новым
индикатором.
