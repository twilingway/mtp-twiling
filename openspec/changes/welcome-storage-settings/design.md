# Design

## Context

IndexedDB используется одинаково в браузере и установленных Android/iOS PWA. Настройки приветствия
относятся к origin/профилю браузера и не гарантируют общий storage между отдельными браузерами.

## Goals / Non-Goals

**Goals:** понятное первое открытие, повторный доступ, явная выборочная очистка текущего профиля.
**Non-Goals:** удаление изображений/ключей, миграция облачного протокола, изменение серверов и
OAuth.

## Decisions

- Устройственная запись welcome в preferences не содержит owner и исключена из portable backup.
  Чтение/запись разрешены до банковского входа. Ошибка IDB показывается, скрытие не объявляется
  сохранённым.
- Приветствие открывается после ready, не перекрывает другое окно, содержит короткие RU/EN
  пояснения, официальный token guide и настройки Т‑Инвестиций, личный Drive, privacy и публичный
  GitHub.
- В аккаунте отдельные разделы подключения/Drive/истории/JSON-переноса; помощь доступна всегда.
- Выбор инструмента и таймфрейма начинается пустым. Строка таблицы выбирает конкретную группу; «Все»
  выбирается явно. Подтверждение содержит выбранные объём/свечи/число групп.
- Все операции статистики/очистки проверяют owner и банковскую session identity до/после await.
  Новый профиль сбрасывает выбор/подтверждение; поздний ответ не публикуется в другом профиле.
- Очистка вызывает существующий controller.clearHistory, сохраняет import/recovery guards и не
  меняет portable drawings/images/prefs/vault. Тест boundary отдельно подтверждает history/coverage
  scope.

## Risks / Trade-offs

- Браузер может очистить IndexedDB → приветствие появится снова; пользователь может экспортировать
  данные.
- Новые свечи могут появиться после очистки → UI объясняет продолжение записи и обновляет
  статистику.
- Визуальная проверка выполняется координатором после сборки; тесты модели её не заменяют.

## Migration Plan

Новая локальная preference не требует изменения версии базы; отказ от feature сохраняет историю.
