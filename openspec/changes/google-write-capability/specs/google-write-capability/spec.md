# Spec Delta

## Purpose

Обеспечить автоматическую и проверяемую условную запись Google Диска без ручного диагностического
шага, сохранив данные и границы аккаунтов.

## ADDED Requirements

### Requirement: Автоматическая проверка ёмкости

Система SHALL проверять полный размер подготовленного пакета до durable pending и отправки
пользовательских данных. Успешная проба SHALL продолжать исходную операцию только при сохранении
локальной ревизии, аккаунта, авторизации и облачных голов.

#### Scenario: Первая запись

- **WHEN** пользователь впервые синхронизирует локальные изменения без доказательства записи
- **THEN** система автоматически проверяет условную запись временного пакета и продолжает исходную
  синхронизацию.

#### Scenario: Изменение во время проверки

- **WHEN** локальные данные, облачные головы или аккаунт меняются во время проверки
- **THEN** устаревшая пользовательская запись не отправляется.

#### Scenario: Неподдерживаемый размер

- **WHEN** пакет превышает максимальный размер поддерживаемой пробы
- **THEN** система сообщает ограничение размера и сохраняет все локальные данные.

### Requirement: Ограниченное доказательство аккаунта

Система SHALL хранить только несекретное доказательство на срок не более 24 часов, связанное с
credential ID, OAuth client ID, протоколом, кодеком, транспортом и проверенным полным размером.
Перенос между credential ID SHALL требовать свежего подтверждения того же аккаунта без расширения
OAuth scope.

#### Scenario: Перезагрузка и повторный вход

- **WHEN** восстановлен тот же credential либо свежая проверка личности подтверждает прежний аккаунт
- **THEN** действительное доказательство используется повторно без новой пробы.

#### Scenario: Нет подтверждения личности

- **WHEN** личность нового credential не подтверждена
- **THEN** доказательство другого credential не используется и выполняется новая проба.

### Requirement: Адресная очистка проб

Система SHALL сохранять журнал зарезервированного собственного probe ID до create и удалять только
подтверждённый собственной namespace, kind и key файл. Неопределённый create SHALL оставаться в
журнале при немедленном 404; ошибка очистки SHALL не отменять подтверждённую возможность записи.

#### Scenario: Потерян ответ create

- **WHEN** создание пробы могло завершиться после потери ответа
- **THEN** журнал сохраняется и повторная очистка выполняется только с авторизацией подтверждённого
  владельца.

#### Scenario: Чужой файл

- **WHEN** свежие метаданные не соответствуют закреплённому probe namespace, kind и key
- **THEN** удаление запрещено.

### Requirement: Координация и наблюдаемость

Система SHALL объединять одновременные проверки одной вкладки и координировать вкладки блокировкой
аккаунта и версии транспорта. Отключение SHALL немедленно прекращать локальную операцию без ожидания
сети; статус SHALL показывать этап, проверенный размер и отложенную очистку.

#### Scenario: Одновременная синхронизация

- **WHEN** две вкладки запрашивают проверку одного аккаунта
- **THEN** после блокировки вторая вкладка повторно читает доказательство и не создаёт лишнюю пробу.

#### Scenario: Отключение

- **WHEN** пользователь отключает Google во время зависшего запроса
- **THEN** текущий прогресс и представление доказательства немедленно очищаются.
