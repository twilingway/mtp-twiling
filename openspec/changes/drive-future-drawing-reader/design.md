# Design

## Context

См. proposal.md. Reader уже различает будущие TA и неизвестные поля; неизвестное имя рисунка раньше
попадало в sanitize/validate и становилось `remote-invalid`.

## Goals / Non-Goals

Цель — узкая проверка capabilities по общему `TOOL_NAMES` до проекции. Новая геометрия, форматы и
изменение raw manual import не входят в задачу: ручной импорт уже отвергает неизвестный тип до
editing.flush.

## Decisions

- Читать только собственные data descriptors пути `drawings[index].items[index].name`. Getter на
  этом пути немедленно отвергается как повреждение, без выполнения. Обычные JSON payload продолжают
  существующую полную валидацию.
- Проверять только неизвестные строки: нестроковые имена и неверные известные рисунки остаются у
  текущего validator.
- Существующий generic unsupported-format flow приостанавливает auth handles без удаления vault;
  новый auth flow не добавляется.

## Risks / Trade-offs

Проверка не является универсальным валидатором произвольных Proxy/прототипов. Это не повод читать
accessor: тесты фиксируют нулевые вызовы getter на добавленном пути. Классификация будущей геометрии
не даёт права писать её из старого приложения.

## Migration Plan

Миграции нет. Отдельный commit интегрируется после независимого review; замороженные build/public не
меняются. Откат возвращает прежнюю ошибку `remote-invalid`, не преобразует сохранения.
