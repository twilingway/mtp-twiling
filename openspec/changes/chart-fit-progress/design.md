# Design

## Context

Обе точки входа вызывают синхронный `fit`; адаптеры уже оборачивают его сохранением камеры.
Котировки часто обновляют TerminalState, поэтому занятость не должна входить в это состояние.

## Goals / Non-Goals

**Goals:** локальное внешнее хранилище на controller, объединение запросов и отмена по жизненному
циклу.

**Non-Goals:** перенос native canvas или математики индикаторов в Workers, изменение алгоритма fit.

## Decisions

- WeakMap хранит отдельную сессию для каждого controller. `useSyncExternalStore` подписывает только
  кнопку и локальный слой; котировки не публикуют снимки занятости.
- Два последовательных animation frame дают браузеру возможность нарисовать статус между ними до
  синхронного fit. Один await frame продолжился бы перед paint. После fit ожидаются минимум два
  кадра и стабильный публичный снимок камеры, с ограниченным числом попыток при недоступном
  readback. Фиксированных задержек нет.
- Перед выполнением и на каждом кадре проверяются текущий адаптер, owner, сессия, revision и
  источник. Подписка на controller и сигнал адаптера отменяет ожидание; размонтирование очищает
  сессию.
- Слой позиционируется абсолютно в области цены, переиспользует существующий ступенчатый loader;
  DOM-порталы не нужны.

## Risks / Trade-offs

- Native canvas остаётся на главном потоке → статус успевает отобразиться, но сама синхронная
  отрисовка может задерживать ввод и анимацию. Это изменение не обещает полной отзывчивости.
- SDK не предоставляет общего события окончания paint → используем кадровые границы и стабильную
  публичную камеру; ограничение попыток исключает бесконечную занятость при недоступном readback.
