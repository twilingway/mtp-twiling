## Context

Событие браузера показывает кнопку установки. Регистрация service worker обслуживает кэш оболочки и
обновление сайта после записи пользовательских данных.

## Decisions

- Сайт использует прежний манифест и показывает кнопку после приглашения браузера. На узком экране
  кнопка и ссылка на справку занимают отдельную строку.
- Инструкция ведёт на официальный файл сертификата. Доверие к сертификату подтверждает пользователь
  в настройках Android.
- Сохраняем адрес и область действия service worker. При подтверждении обновления оболочка сначала
  завершает запись данных. Хранилища профиля сохраняют свои схемы и ключи.
- Только точный `new URL("manifest.webmanifest", scope).pathname` после прежних GET/origin/scope/
  version-проверок использует network-first с `cache: "no-cache"` для HTTP-перепроверки. Query не
  меняет выбор маршрута. Успешный ответ сразу возвращается; исключение или non-OK допускают
  `cache.match(..., { ignoreSearch: true })`. Без кеша возвращается исходный HTTP-ответ или ошибка.
- Сетевой манифест не записывается в кеш активной сборки: её install-time snapshot остаётся
  согласованным. Обобщение network-first на оболочку/активы и смена URL значков не требуются.

## Risks / Trade-offs

Браузер определяет доступность приглашения и управляет установленными экземплярами. Новая оболочка
открывается после штатного обновления. Обновление значка уже установленного Android-приложения
зависит от расписания браузера и ОС; исправление устраняет выдачу старого манифеста service worker,
не обещая немедленную смену значка.
