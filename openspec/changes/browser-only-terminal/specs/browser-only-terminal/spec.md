## ADDED Requirements

### Requirement: Запуск и установка терминала

Терминал SHALL открываться во вкладке и предлагать установку, когда браузер предоставляет
приглашение.

#### Scenario: Открытие терминала

- **WHEN** пользователь открывает терминал по ссылке без приглашения браузера
- **THEN** терминал показывает рабочее пространство во вкладке

#### Scenario: Доступна установка

- **WHEN** браузер сообщает о возможности установки
- **THEN** терминал показывает кнопку «Установить приложение», которая открывает диалог браузера
- **AND** на узком экране кнопка и инструкция по сертификату помещаются в отдельной строке шапки

#### Scenario: Приглашение пришло при загрузке

- **WHEN** браузер сообщает о возможности установки до завершения загрузки терминала
- **THEN** после загрузки кнопка доступна и открывает диалог этого приглашения

### Requirement: Обновление открытого сайта

Терминал SHALL сохранять пользовательские данные перед применением новой версии во вкладке.

#### Scenario: Обновление подтверждено

- **WHEN** пользователь нажимает «Обновить» в открытой вкладке
- **THEN** терминал завершает сохранение, активирует новую версию и перезагружает вкладку

#### Scenario: Сохранение завершилось ошибкой

- **WHEN** записать данные перед обновлением не удалось
- **THEN** открытая версия продолжает работу и сообщает, что обновление отложено

### Requirement: Справка по подключению Т‑Банка на Android

Терминал SHALL предоставлять доступную по прямой ссылке инструкцию по подключению на Android.

#### Scenario: Пользователь открывает справку

- **WHEN** пользователь выбирает ссылку на сертификат в шапке или настройках либо открывает URL
  справки
- **THEN** он видит способ запуска в Яндекс Браузере, официальную ссылку на сертификат и шаги
  подтверждения установки в настройках Android для работы в Chrome

### Requirement: Актуальный манифест установки

Терминал SHALL отдавать свежий доступный по сети манифест установки по прежнему адресу, включая
запросы с query, а при сетевом сбое или неуспешном HTTP-ответе использовать кеш текущей оболочки.
Правило SHALL относиться только к точному пути манифеста внутри области терминала.

#### Scenario: В кеше старые ссылки на значки

- **WHEN** в кеше манифест со старым значком, а сеть возвращает успешный манифест с новыми значками
- **THEN** браузер получает новый манифест без записи в кеш активной сборки и без смены id,
  start_url или scope

#### Scenario: Сеть недоступна или сервер отвечает ошибкой

- **WHEN** запрос манифеста завершается сетевой ошибкой или неуспешным HTTP-ответом и есть кеш
- **THEN** браузер получает кешированный манифест текущей оболочки

#### Scenario: Нет доступной копии

- **WHEN** запрос манифеста завершается ошибкой, а кешированной копии нет
- **THEN** сохраняется исходная сетевая ошибка либо неуспешный HTTP-ответ без подмены оболочкой

#### Scenario: Изоляция обновления

- **WHEN** браузер запрашивает другие ресурсы, API, чужой origin или путь вне области терминала
- **THEN** применяется прежняя обработка этих запросов, кеш оболочки сохраняет свою сборку, а
  активация новой версии требует явного подтверждения
