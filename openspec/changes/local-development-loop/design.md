# Локальная разработка

## Context

Текущая команда dev сначала выполняет релизную сборку с проверкой типов. Внесение каждой правки
требует ручного повторения сборки. Полный check нужен перед вливанием, а локальные итерации должны
показывать изменения сразу.

## Decisions

- Использовать установленный esbuild в режиме context/watch без новых зависимостей.
- Общий список точек входа и лицензий выделить из релизной сборки без изменения её поведения.
- Результаты разработки хранить отдельно в игнорируемом artifacts/dev-runtime.
- Автоматическое обновление работает через локальное соединение с сервером разработки. Service
  worker не должен кешировать этот режим.
- Сервер слушает loopback. Телефон по USB получает тот же адрес через adb reverse.
- При остановке закрывать наблюдатели, подключения и контекст сборки. Не запускать отдельные
  переживающие сессию процессы.

## Risks / Trade-offs

- Инкрементальная сборка проверяет синтаксис, но не заменяет TypeScript, тесты и проверку
  спецификаций.
- Полные проверки запускаются перед вливанием. При небольшой правке используются подходящие точечные
  проверки и проверка поведения в браузере.
- Адрес на телефоне работает, пока подключён USB и запущен локальный сервер.
