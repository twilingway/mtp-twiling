# Design

## Context

См. proposal.md. calendarAxisTicks ограничивает to последней реальной свечой. LW primitive уже
передаёт полный logical visible range; KLine XAxis callback получает обрезанный range и должен
читать chart.getVisibleRange().realFrom/realTo. Существующие logicalForTime/timeForLogical
экстраполируют данные, но живут в chart adapter.

## Goals / Non-Goals

**Goals:** общая чистая проекция и видимые календарные кандидаты в доступном будущем поле без
изменения данных.

**Non-Goals:** полный пан в пустое будущее, ослабление min-last-bars, фальшивые OHLC/whitespace
series, продление индикаторов и изменение runtime общей сборки.

## Decisions

- Перенести существующие logicalForTime/timeForLogical в чистый timestamp-only projected-time helper
  с re-export из adapter.ts; оставить прежние математические результаты.
- Горизонт — shiftUtcMonths(last.timestamp, 9). Реальные индексы читают исходные timestamps; будущие
  вычисляют timestamp лениво по той же формуле.
- Для будущего диапазона отбирать кандидатов с экранным шагом и отдельным поиском переходов
  месяца/дня. Не создавать девятимесячный массив и не обходить каждую минуту. Объединённые
  реальные/будущие кандидаты проходят общий приоритет и collision filter.
- Календарные части и подписи получать из существующего calendarAxisDisplay. D/W/M используют
  UTC-дату; intraday — выбранную зону.
- KLine получает реальные геометрические границы из getVisibleRange; LW продолжает пользоваться
  существующим primitive без новой серии.

## Risks / Trade-offs

- Существующий native pan удерживает реальные свечи → горизонт может быть дальше видимого поля; это
  документированное ограничение, камера сохраняется.
- Низкий масштаб minute-графика → кандидаты разрежаются в экранном пространстве, месячные переходы
  сохраняют приоритет.
- Переход DST → каждый кандидат сравнивается с предыдущим реальным/проецируемым индексом и
  форматируется общей зоной.
- Браузерная приёмка общей версии → выполняется координатором после source-интеграции, без заявления
  визуальной готовности по unit tests.
