# Хранение и перенос

## Context

Старый формат загружает цепочку снимков и требует наличия каждого родителя. Идентификатор, созданный
в закрытом приватном хранилище, после закрытия окна нельзя связать с новым сеансом.

## Decisions

- Обычный профиль повторно использует существующий локальный идентификатор. Первая запись ID
  выполняется в транзакции IndexedDB. Для явно выбранного тестового режима используется один
  зарезервированный идентификатор в пределах облачного рабочего пространства.
- Один облачный файл содержит текущую и предыдущую версии с проверяемой последовательностью.
  Транспорт повторно использует физический идентификатор файла и проверяет подтверждение записи.
  Штатная запись переносит текущую версию в предыдущую. Восстановление предыдущей версии создаёт
  новую ревизию с её содержимым.
- Перед включением записи проверяется условное обновление файла и доступность метки версии в
  браузере. Проверка использует технический файл с синтетическими данными и конкурирующими
  отправками по тому же multipart и media маршруту. Нужны доступный сильный ETag, один ответ 412 и
  подтверждённое повторным чтением содержимое победившей версии. Лимит загрузки относится к
  проверенному объёму и текущему сеансу авторизации.
- В локальном журнале сохраняются физический идентификатор, метка исходной версии и ожидаемая
  контрольная сумма. При неопределённом ответе повторное чтение ищет эту ревизию в текущей и
  предыдущей версиях. Если доказательств недостаточно, сохранение остаётся неподтверждённым.
- Переход запечатывает экспорт с полным содержимым кандидатов и их зависимостей, проверяет новые
  файлы и сохраняет отпечаток проверенного архива в новой версии. Архив хранит отдельные двоичные
  секции с контрольными суммами для JSON и изображений. Для очистки требуется внешнее подтверждение
  остановки старых клиентов и завершения их запросов. Поздний файл требует нового плана. Удаление
  идёт от дочерних снимков к родителям, затем удаляются их архивированные данные.

## Risks / Trade-offs

- Google Drive удаляет данные приложения без корзины. Экспорт проверяется чтением, операция
  показывает идентификаторы и последствия, а частично завершённая очистка ведёт журнал.
- Метка из списка файлов пригодна для кэша. Право условного обновления должно подтверждаться
  отдельным запросом и воспроизводимой проверкой конкуренции.
- Неизвестные идентификаторы и несведённые ветки остаются доступны для ручной сверки.
- Просмотр заголовков ограничен по размеру и количеству. Восстановление проверяет обе полные версии
  файла. Архив ограничен 512 МиБ и 2048 снимками.
- Координатор хранит транспорт, состояние авторизации и этапы одной операции вместе, чтобы при
  отключении отменять их одной сменой сеанса. Код проверки архива, транспорта, очистки и решений
  синхронизации вынесен в отдельные модули.
