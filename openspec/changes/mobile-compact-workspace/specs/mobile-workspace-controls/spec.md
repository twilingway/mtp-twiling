## ADDED Requirements

### Requirement: Верхняя мобильная панель рабочего пространства

На ширине до 800 px приложение SHALL показывать в верхней строке кнопку с текущим числом графиков.
Постоянные нижние полосы управления SHALL отсутствовать.

#### Scenario: Изменение раскладки и истории

- **WHEN** пользователь открывает верхнюю панель при выбранном графике
- **THEN** доступны все раскладки от 1 до 16, текущая глубина истории этого графика и выбор часового
  пояса
- **AND** изменение глубины истории оставляет глубину остальных графиков прежней

#### Scenario: Переключение панелей

- **WHEN** пользователь выбирает котировки или дерево объектов
- **THEN** нужная панель открывается вместо области графика
- **AND** пункт «График» возвращает к графику

#### Scenario: Мобильные команды приложения

- **WHEN** пользователь открывает верхнюю панель
- **THEN** доступны полноэкранный режим и установка при наличии приглашения браузера
- **AND** раскрытая область закрывается клавишей Escape или касанием снаружи

#### Scenario: Настройка рисунка

- **WHEN** пользователь нажимает кнопку настроек рядом с рисунком в дереве объектов
- **THEN** открываются настройки этого рисунка активного графика

### Requirement: Видимая высота мобильного рабочего пространства

В мобильном браузере приложение SHALL ограничивать нижнюю границу рабочего пространства доступной
областью окна, сохраняя шкалу времени графика над интерфейсом браузера. Размер SHALL учитывать
динамическую высоту CSS viewport и доступную нижнюю границу visual viewport без изменения масштаба
графика или повторной загрузки данных. Без Visual Viewport API SHALL сохраняться CSS-расчёт высоты.

#### Scenario: Обычная вкладка с панелями браузера

- **WHEN** адресная панель браузера открывается или скрывается на мобильном устройстве
- **THEN** рабочая область помещается до доступной нижней границы окна
- **AND** шкала времени не уходит под панель браузера
- **AND** интерфейс учитывает safe-area внутри общей высоты приложения

#### Scenario: Поворот и экранная клавиатура

- **WHEN** устройство поворачивается или экранная клавиатура уменьшает видимую область
- **THEN** нижняя граница рабочего пространства обновляется по актуальной геометрии окна
- **AND** при сдвиге visual viewport верхняя привязка приложения сохраняется, а нижняя граница
  учитывает сумму сдвига и видимой высоты, ограниченную высотой layout viewport

#### Scenario: Масштабирование страницы и режим приложения

- **WHEN** пользователь масштабирует страницу жестом pinch
- **THEN** приложение не пересчитывает высоту рабочего пространства по уменьшенной области zoom

#### Scenario: Отдельное приложение

- **WHEN** приложение открыто отдельно как PWA без панелей браузера
- **THEN** используется вся доступная динамическая высота с учётом safe-area
