# Design

## Context

См. proposal.md. Чистое ядро уже имеет проверяемые TechnicalIndicatorInstance с
id/params/pane/order, семь вычислений и historyRequirement. Старые флаги управляют MTP, объёмом и
фиксированными SMA20/EMA50. Native adapters пока знают только эти флаги; высота сохраняется для
volume_pane в KLine.

## Goals / Non-Goals

Goals: подключить единый экземплярный контракт к обоим движкам, независимым настройкам, поиску и
переносимой раскладке. Сохранять камеру при оформлении, перестановке и изменении высоты.

Non-Goals: исполнение сериализованного JavaScript/Pine, серверные вычисления и имитация недоступных
рыночных данных. Каталог стратегий и опционов не смешивается с категорией 127 ТА-индикаторов.

## Decisions

1. Добавить optional technicalIndicators:TechnicalIndicatorInstance[] в переносимые preferences,
   переиспользуя строгий существующий validator. Старые flags не преобразовывать массово и не
   удалять: это сохраняет текущие presets и совместимость. Новые экземпляры независимы от них.
2. Группировать нижние экземпляры по pane.id. Порядок внутри группы определяется order с устойчивым
   id как разрешением равенства. Раскладка панелей хранит стабильные id, высоту и свёрнутость.
   Геометрия на малом экране ограничивается только при отображении, без записи адаптации в профиль.
3. Расчёт использовать из общего чистого runtime, нативным библиотекам передавать готовые ряды.
   Встроенные одноимённые функции движков не являются взаимозаменяемым источником формул и seeds. На
   prepend/correction выполняется корректный пересчёт полного подтверждённого входа.
4. Добавить отдельные модули рендеринга и геометрии панелей. Привязка рисунков, перекрестия цены,
   сетки и ценового countdown остаётся ограничена ценовой панелью; общий X синхронизирован.
5. Чистая функция перестановки изменяет порядок, а контроллер сохраняет результат с owner/session/
   import/revision guards. UI предоставляет drag и клавиатурную альтернативу. Инстансы не
   идентифицируются названиями или индексом массива.
6. Search catalog содержит фиксированную metadata-инвентаризацию. Computed availability связывается
   с реально подключённым определением; иные состояния разделяют pending implementation и confirmed
   missing data. Для добавляемых math families обязательны первичные formula/default references и
   fixtures. Публичный reference не содержит исполнительного кода.
7. Native обновления настроек и порядка выполняются без fitContent/reset. Если необходим remount,
   применяются текущие scoped camera guards и точное восстановление. Внешние observer не видят
   промежуточные draft-настройки; сохранение параметров имеет явную границу подтверждения.

## Risks / Trade-offs

- Разные шкалы и pane API → общий контракт плюс независимая визуальная проверка обоих движков.
- Различный EMA/RSI seed при обрезке истории → соблюдение historyRequirement и отсутствие обещания
  битового совпадения с другой глубиной истории.
- Новый preference вырезается Drive allowlist → storage/JSON/Drive round-trip включить в тот же
  контрактный коммит, до подключения UI.
- Переполнение вертикальной высоты → ограничение геометрии с сохранением предпочтений, проверка
  нескольких панелей и мобильного viewport.
- Metadata ошибочно выглядит готовым вычислением → отдельный completion manifest всех 127 записей;
  незавершённая строка не считается реализованным ТА.

## Migration Plan

Сначала optional persistence contract и тесты старого backup. Затем семь готовых вычислений в обоих
движках, настройки/порядок/высоты, общий search catalog. Остальные math families подключаются
изолированными пакетами к проверенному registry. Каждый пакет проходит source и browser gate; версия
увеличивается координатором общей сборки. Старые flags и записи не очищаются при откате.
