# Design

## Context

См. proposal.md. PWA не имеет backend для данных пользователя. Существующая Backup v1 содержит
разрешённые данные и необязательную историю/котировки; её validator допускает дополнительные поля.

## Goals / Non-Goals

**Goals:** независимое typed core, тестируемое fake HTTP и GIS; безопасная последующая
UI-интеграция. **Non-Goals:** автоматическое слияние, серверные токены, история, shared Drive,
retention и bank API.

## Decisions

- GIS подготавливается заранее; запрос токена синхронно запускается обработчиком клика. Единственный
  scope drive.appdata, без refresh token, автоматического popup или токена в storage.
- appDataFolder + appProperties namespace `mtp-drive-v1`. В одном личном Drive один workspace.
  Локальная связь профиля хранится отдельно от bank owner, случайный connection marker не выводится
  из ключа. Root integration отвечает за подтверждение привязки локального профиля.
- Неизменяемые снимки DAG с UUID устройства/узла и parents. Общего перезаписываемого указателя нет.
  Каждая ветвь сохраняется; publish проверяет известные вершины, resolve явно включает все вершины.
- Явная глубокая проекция разрешённых полей + validateBackup. Изображения вынесены в SHA256 blobs;
  JSON с метаданными хранит пустые image.data. Снимок публикуется после blob uploads.
- Multipart для небольших файлов, resumable для больших; status query после потери ответа;
  ограниченные retry/backoff для 429/5xx/rateLimitExceeded. GET скачивание проверяет размер и
  SHA256.
- Имена/метаданные не содержат owner/ключ. Нет удаления и перезаписи удалённых данных. Повторный
  upload после потери ответа может оставить безопасный дубликат; одинаковые узлы дедуплицируются.

## Risks / Trade-offs

- [Рост append-only данных] → отдельная будущая retention-функция, без скрытого удаления.
- [Listing не является транзакцией между устройствами] → DAG сохраняет поздние ветви; повторный
  inspect показывает конфликт. Нет обещания блокировки распределённых гонок.
- [Reload прерывает resumable session] → повторить upload; завершённые content blobs
  переиспользуются.
- [Много снимков] → bounded listing/manifest limits; превышение останавливает sync без pruning.
- [OAuth popup и реальные quota не проверены fake tests] → отдельная ручная проверка после UI glue.

## Migration Plan

Сначала включить core тесты и проверки, затем root интегрирует отдельный UI bridge с подтверждением
импорта и привязки. Откат выключает Drive UI; локальные данные и удалённые снимки сохраняются.
