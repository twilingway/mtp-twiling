# Design

## Context

См. proposal.md. PWA не имеет backend для данных пользователя. Существующая Backup v1 содержит
разрешённые данные и необязательную историю/котировки; её validator допускает дополнительные поля.

## Goals / Non-Goals

**Goals:** независимое typed core, тестируемое fake HTTP и GIS; раздел аккаунта с ручной и
автоматической синхронизацией и безопасным импортом. **Non-Goals:** автоматическое слияние,
серверные токены, история, shared Drive, retention и bank API.

## Decisions

- GIS подготавливается заранее. Запрос токена синхронно запускается обработчиком клика. Единственный
  scope drive.appdata. Действующий токен сохраняется в локальном зашифрованном vault до исходного
  срока. Повторная авторизация после истечения требует клика.
- appDataFolder + appProperties namespace `mtp-drive-v1`. В одном личном Drive один workspace.
  Локальная связь профиля хранится отдельно от bank owner, случайный connection marker не выводится
  из ключа. Root integration отвечает за подтверждение привязки локального профиля.
- Неизменяемые снимки DAG с UUID устройства/узла и parents. Общего перезаписываемого указателя нет.
  Каждая ветвь сохраняется; publish проверяет известные вершины, resolve явно включает все вершины.
- Явная глубокая проекция разрешённых полей + validateBackup. Изображения вынесены в SHA256 blobs;
  JSON с метаданными хранит пустые image.data. Снимок публикуется после blob uploads.
- Multipart для небольших файлов, resumable для больших; status query после потери ответа;
  ограниченные retry/backoff для 429/5xx/rateLimitExceeded. GET скачивание проверяет размер и
  SHA256.
- Имена/метаданные не содержат owner/ключ. Нет удаления и перезаписи удалённых данных. Повторный
  upload после потери ответа может оставить безопасный дубликат; одинаковые узлы дедуплицируются.
- Coordinator привязан к owner и экземпляру банковской сессии; изменение любого из них прекращает
  Google-сессию и старую работу. Привязка/случайный device ID, digest, родители и время sync
  хранятся в IndexedDB отдельно от переносимых preferences. Восстановление Google-сессии проверяет
  владельца, Client ID и срок токена.
- Изменения preferences/рисунков/изображений/списка запускают debounce 1500 мс. Цены и свечи не
  помечают профиль изменённым. При включённой автоматике видимая страница проверяется при focus и
  раз в 60 секунд. Ручной вход сразу запускает проверку. Новый профиль публикует первый снимок в
  пустом облаке. Первое непустое подключение требует выбора. Последующие чистые устройства применяют
  удалённый снимок через очередь.
- Конфликт показывает числа инструментов/рисунков/изображений и дату всех текущих вершин (до
  восьми). Выбор проверяется повторным экспортом/digest, revision и inspect. Изменение после
  preview/pull отменяет применение и требует новой проверки. Снимки не удаляются.
- Если в проверенном каталоге отсутствует ранее принятая вершина профиля, coordinator готовит тот же
  явный выбор, в том числе для пустого каталога. Сопоставление использует всю историю, чтобы ранее
  принятая вершина могла остаться предком единственной новой вершины.
- Portable replace требует полный layout/watchlist/drawings/images/views и заменяет только portable
  данные текущего owner одной IDB-транзакцией. История/vault/чужие owner/Drive-привязки остаются.
  Обычный импорт сохраняет merge. Guard проверяется после очереди/flush/saveView и внутри
  transaction; onCommitted переключает подавление собственного import echo перед восстановлением
  профиля.
- Drive import захватывает AbortSignal Google-сессии до await и передаёт его до IDB transaction.
  Отмена до native commit вызывает tx.abort; complete/error/abort/ошибка writer удаляют listener.
  После начала native commit InvalidStateError от позднего abort не превращается в ошибку уже
  записанной транзакции. Обычный файловый merge-import эту гарантию не получает.
- Раздел аккаунта загружает GIS заранее; кнопка включает popup непосредственно по клику. Истечение
  даёт явный повторный вход. Локальный static server/nginx разрешают только необходимые Google CSP
  endpoints и COOP same-origin-allow-popups; privacy доступна отдельным статическим HTML без ключа.

Направление и исход явного выбора хранятся в состоянии подключения. Пока проверяются версии или
передаются данные, кнопки выбора заняты. Подтверждение привязано к завершению существующей записи
или применения и локальному сохранению принятой версии. Обновлённый список требует повторного
выбора. Ошибка использует действующие действия повтора и входа.

## Risks / Trade-offs

- [Рост append-only данных] → отдельная будущая retention-функция, без скрытого удаления.
- [Listing не является транзакцией между устройствами] → DAG сохраняет поздние ветви; повторный
  inspect показывает конфликт. Нет обещания блокировки распределённых гонок.
- [Reload прерывает resumable session] → повторить upload; завершённые content blobs
  переиспользуются.
- [Много снимков] → bounded listing/manifest limits; превышение останавливает sync без pruning.
- [OAuth popup и реальные quota не проверены fake tests] → отдельная ручная проверка после UI glue.

## Migration Plan

Сначала проверить pure/integration tests и общий check, затем root выполняет отдельную визуальную
проверку, настоящий OAuth и два устройства. Реальные OAuth/Drive и Production consent остаются
непроверенными до этого шага. Откат выключает Drive UI; локальные данные и удалённые снимки
сохраняются.
