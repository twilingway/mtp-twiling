# Design

## Context

Watchlist хранит реальные MarketRow отдельным snapshot, включая одинаковые тикеры разных UID и
canonical Bybit ID. Запись двух независимых хранилищ для одного переноса неатомарна.

## Goals / Non-Goals

Goals: управляемые разделы, точный переносимый порядок отображения, сохранение реальных инструментов
при удалении заголовка, работающие desktop/mobile/keyboard действия.

Non-Goals: новая версия приложения, публикация, изменение провайдеров или истории, серверная
синхронизация котировок.

## Decisions

- Optional `watchlistSections` содержит `version:1` и массив дискриминированных section/instrument
  entries. Заголовок содержит id/title/collapsed. Ссылка на реальный инструмент содержит
  uid/symbol/occurrence; это метаданные, а не MarketRow.
- Ledger управляет только отображением. Client rows, подписки, UID, providerRef и запросы
  Т-Банка/Bybit не меняются. Export переносит и реальные rows, и ledger.
- Reconcile удаляет отсутствующие ссылки, добавляет новые реальные инструменты в конец и сохраняет
  пустые заголовки. Старые prefs дают исходный порядок. Идентичность UID+symbol+occurrence различает
  same ticker разных UID; точные дубли адресуются порядковым вхождением.
- Добавление перед контекстной строкой делит текущий раздел: нижележащие инструменты до следующего
  header входят в новый. Добавление на фоне создаёт пустой раздел в конце. Ограничение: 200
  заголовков, 10000 ссылок, название 1–80 символов.
- Удаление заголовка извлекает его блок и помещает инструменты в конец верхнего уровня перед первым
  оставшимся заголовком. Они не становятся членами предыдущего раздела.
- Перенос инструмента до/после заголовка меняет членство по границе. Перенос header переносит целый
  блок, включая скрытых членов. Сортировка применяется внутри групп; успешный ручной перенос
  выключает сортировку. Фильтрация не меняет ledger.
- Верхний уровень всегда остаётся начальным блоком. Перенос заголовка к его инструментам означает
  границу после верхнего уровня; перестановка разделов не захватывает эти инструменты.
- Мобильный select в контекстном меню переносит инструмент в выбранный раздел или на верхний
  уровень. Alt+стрелки и команды выше/ниже заменяют drag. SVG и общие theme vars обеспечивают
  привычные состояния.
- Очередь merge читает свежие prefs после предыдущей операции. Sticky
  owner/session/import/profileTransition/route guard отменяет устаревшую операцию даже после
  возврата исходного профиля. Ошибка optimistic setPreferences выполняет CAS rollback только нашего
  section-поля, сохраняя чужие prefs и более поздний ledger.
- Порядок выбора при восстановлении отсутствующего инструмента и список выбора инструментов
  используют ledger. Скрытые collapse-члены остаются доступными в поиске; сворачивание не меняет
  текущий график.
- Validator проверяет точные plain data shapes без accessors, прототипов, лишних полей, повторных
  ссылок и превышения границ. Drive проверяет поле до проекции, чтобы запрещённые данные не исчезали
  молча.

## Risks / Trade-offs

Проверка границ после source integration выявила старый обход sticky cancellation в canonical
reorder и fallback после удаления выбранной строки. Оба действия вынесены в
`controller-watchlist.ts` с захваченным owner/client/revision и подпиской на
import/profileTransition. Отложенный fallback дополнительно передаёт valid callback в
setPreferences: завершённый import или новый ledger не перезаписывается прежним выбором. Canonical
row storage/API путь сохранён; guard не отменяет уже начавшийся storage commit, но запрещает
последующую публикацию в чужой профиль.

Точные дубли UID+symbol не имеют собственного постоянного ID; после удаления одного такого дубля
сохраняется порядок вхождений. Штатный setPreferences сохраняет вид графика, но section patch не
меняет маршрут, историю или камеру. Визуальная проверка выполняется координатором в отдельном свежем
агенте после source integration.

## Open Questions

Нет; контракт display ledger принят координатором.
