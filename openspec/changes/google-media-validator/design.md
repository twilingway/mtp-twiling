## Context

Чтение и запись выполняются непосредственно браузером с текущим доступом `drive.appdata`. При живой
проверке технического файла ответ Drive v3 на чтение содержимого и метаданных не предоставил ETag
JavaScript. Сильная метка v2 и условная запись v2 прошли отдельную проверку.

## Decisions

- Полное чтение выполняет GET метаданных v2, GET содержимого v3 и второй GET метаданных v2 без
  браузерного кэша. Принимаются совпадающие ID, версия, размер, сильный ETag и серверный SHA-256.
  SHA-256 скачанных байтов должен совпадать с серверным.
- Для несогласованности предусмотрены до трёх попыток чтения с общей границей времени и отменой.
  Чтение заголовка при перечислении остаётся ограниченным по размеру и служит только для
  предварительного просмотра. Запись проверяет его по полному файлу.
- Замена выполняется v2 `files.update` по существующему ID с `uploadType=media` и `If-Match`.
  Подтверждение сверяет ID, размер и сильный ETag ответа с согласованным чтением и проверяет
  упакованные версии. В Chrome поле `version` в ответе PUT отличилось от более позднего
  согласованного чтения при совпадающем ETag. Для чтения проверяется его собственная версия
  метаданных. Ответ `412` передаётся как конфликт. Неизвестный результат сохраняется в журнале.

## Risks / Trade-offs

- Полное чтение требует двух дополнительных запросов метаданных. Перечисление и чтение заголовков
  сохраняют прежний сетевой путь.
- При отсутствии или несовпадении SHA-256 клиент повторяет чтение. Когда попытки исчерпаны, клиент
  завершает операцию без выдачи метки для записи. Контейнер проверяется также по собственным хешам.
- Перед использованием в DEV требуется повторить живую проверку с фактическим форматом файла. Доступ
  к записи действует после успешной пробы в текущем сеансе авторизации.
