# Design

## Context

Свечи используют UTC milliseconds. Клиент Т‑Банка предоставляет отменяемый REST request. Ответ
TradingSchedules содержит дублирующиеся регулярные интервалы, аукционы и отдельные периоды клиринга;
exchange может различаться регистром.

## Goals / Non-Goals

**Goals:** чистая проверяемая модель времени, подтверждённые сессии, отдельный сетевой кэш.

**Non-Goals:** торговые операции, прогноз расписания при отсутствии данных, фиксированные часы
биржи, месячный таймфрейм в текущем изменении.

## Decisions

- Внутридневная длительность считается от timestamp свечи; календарные периоды выделены отдельной
  функцией с UTC Date arithmetic, без предположения о длине месяца или года.
- Граница внутридневной свечи ограничена концом торгового дня. Клиринг и аукцион внутри её интервала
  лишь скрывают отсчёт; они не меняют номинальное время закрытия свечи.
- Нормализованный календарь хранит дату, флаг торгового дня, начало/конец и объединённые регулярные
  интервалы; клиринг и аукционы не активируют отсчёт.
- UID разрешается через GetInstrumentBy один раз на клиент. TradingSchedules кэшируется по exchange
  и полному диапазону дат, а не timestamp отдельной свечи; отменённые и ошибочные запросы не
  отравляют кэш.
- Готовое расписание кэшируется на 5 минут, обычная ошибка — на 60 секунд по UID или диапазону
  биржи. Смена свечи не сбрасывает задержку повторения; AbortError не создаёт negative cache.
- Граница дневной свечи берётся из её торгового дня, недельной — из подтверждённых дат от активного
  торгового дня до конца недели. Прошедшие дни не нужны для будущей границы свечи. Во время
  перерывов таймер скрыт.
- TradingSchedules не принимает прошлую дату from: запрос начинается не раньше текущей даты UTC.
  Устаревшая свеча не вызывает запрос прошлого расписания. Ночная сессия с недоступной датой
  предыдущего торгового дня скрывается при отсутствии подтверждённого кэша.
- Подтверждённый календарь текущего клиента хранит прошедшую дату до фактического конца ночной
  сессии. Для переиспользования обязательна известная связь UID с площадкой; другой клиент или
  неизвестный UID не наследуют эти данные. Недельное расписание объединяет активный ночной день из
  кэша с новыми будущими датами, не запрашивая историю.
- Контроллер проверяет актуальность клиента и владельца после ожидания. Ошибка необязательного
  календаря не создаёт toast.

## Risks / Trade-offs

- Изменение расписания в течение дня → кэш расписания ограничен по времени и обновляется при смене
  даты UTC.
- Неизвестные типы сессий или неполные ответы → таймер скрывается до подтверждённого расписания.
