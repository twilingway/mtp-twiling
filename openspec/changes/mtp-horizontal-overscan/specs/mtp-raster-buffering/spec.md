# Spec Delta

## Purpose

Заранее подготовленные реальные линии МТП по краям viewport сохраняют непрерывность при движении
пальцем и тачпадом, не искажая точный видимый график и не блокируя основной поток.

## ADDED Requirements

### Requirement: Real horizontal reserve

Система SHALL готовить линии существующих свечей по обе стороны видимого диапазона в пределах
ограниченного запаса, а не только расширять прозрачную поверхность.

#### Scenario: Pan into prepared bars

- **WHEN** пользователь сдвигает график в любую сторону в пределах достигнутого запаса
- **THEN** открывающиеся реальные МА уже присутствуют у края без пустой полосы
- **AND** отсутствующая история и периоды без достаточного прогрева не заменяются придуманными
  значениями

#### Scenario: Wide plot and small panes

- **WHEN** ширина области отдельного графика меняется между телефоном, малой панелью и большим
  графиком
- **THEN** целевой запас с каждой стороны равен `max(96 CSS px, actual plot CSS width / 2)`
- **AND** фактический запас ограничен прежними 4096 px и 4 Mi-pixels независимо от UA и числа
  панелей

### Requirement: Exact visible core

Система SHALL сохранять точные пиксели исходного видимого участка, периоды, прогрев, стили, sampling
phase и плотность после добавления запаса.

#### Scenario: Sampling boundary and fractional DPR

- **WHEN** при той же камере включён запас на диапазонах у границы sampling и дробном DPR
- **THEN** RGBA видимого core совпадает с прежним exact renderer без отличающихся пикселей
- **AND** широкие полупрозрачные линии, cap/join и miter сохраняются

### Requirement: Refill before exposure

Система SHALL обновлять запас до его исчерпания с ограниченной очередью и частотой; подготовка
метаданных на кадр не должна обходить историю.

#### Scenario: Approaching a prepared edge

- **WHEN** жест расходует существенную часть доступного запаса, пока viewport ещё покрыт
- **THEN** начинается bounded refill без ожидания появления чёрной полосы
- **AND** refill начинается при остатке половины фактически доступного запаса, без ограничения 48
  CSS px
- **AND** таймеры и ответы Worker не создают полный snapshot сами по себе

#### Scenario: History boundary

- **WHEN** за достигнутым краем нет загруженных свечей
- **THEN** система не генерирует несуществующие линии и не запускает бесконечные одинаковые refill

### Requirement: No exposed gap while waiting

Система SHALL сохранять МА на всём доступном текущем диапазоне, когда жест опережает подготовку
запаса; временное превью не считается точным кадром.

#### Scenario: One pixel or whole screen exposed

- **WHEN** актуальной поддерживаемой проекции не хватает одного пикселя покрытия либо всего viewport
- **THEN** текущий bounded coarse отображается вместо неполного bitmap без пустой полосы и двойной
  альфы
- **AND** pending завершается только после актуального exact blit

### Requirement: Bounded ownership and resources

Система SHALL сохранять ограничения размера поверхности и очереди, отбрасывать чужой или устаревший
результат и освобождать bitmap/таймеры при завершении владельца.

#### Scenario: Resize under memory budget

- **WHEN** высокий DPR или resize ограничивает доступную поверхность
- **THEN** фактический запас уменьшается, стороны остаются не больше 4096 px, площадь не больше 4
  Mi-pixels
- **AND** применяется прежний fallback без бесконечного ожидания

#### Scenario: Reversal and source replacement

- **WHEN** жест развёрнут либо инструмент, reset, стили или DPR изменены до ответа Worker
- **THEN** выбирается только пригодный текущий слой; obsolete bitmap закрывается
- **AND** disable, destroy и error освобождают очередь и таймеры
