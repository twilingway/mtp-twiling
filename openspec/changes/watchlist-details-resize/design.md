# Design

## Context

Сейчас details ограничена max-height 65%/680px и сжимает flex-список. Нужна фиксированная
пользовательская граница независимо от содержимого.

## Goals / Non-Goals

**Goals:** изолировать управление жестом и геометрию от Watchlist, оставить минимум места обеим
областям.

**Non-Goals:** изменение котировок, API, графиков, общих стилей и версии приложения.

## Decisions

- Optional `rightDetailsHeightRatio` в TerminalPreferences и ProfilePreferences, диапазон 0.15–0.85,
  стандарт 0.45. Доля переносима между устройствами; абсолютные пиксели отвергнуты.
- Новый компонент владеет Pointer Capture и CSS-переменной родительской панели. Список получает
  отдельную flex-обёртку. Новая CSS переопределяет прежний max-height.
- ResizeObserver учитывает панель, шапку, поиск, счётчик и нижнюю подпись. Минимум списка включает
  элементы управления и 60px строк, минимум карточки 96px; при экстремально низком окне обе области
  получают пропорциональный минимум с прокруткой.
- Сохранение только по завершению жеста или клавише; resize viewport не пишет предпочтения. Guard
  отменяет отложенную запись при смене владельца, импорте, ревизии или закрытии панели.
- Поле добавляется только в существующие валидатор и Drive allowlist, без schema bump.

## Risks / Trade-offs

- Очень низкое окно не вмещает все элементы управления → список целиком тоже может прокручиваться.
- CSS подключает координатор в public/index.html после instrument-details.css; визуальная проверка
  выполняется координатором после интеграции.
