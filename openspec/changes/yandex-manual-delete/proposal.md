# Proposal

## Why

Пользователь должен удалять выбранные старые сохранения Яндекса вручную, видя точную версию и
причину защиты оставшихся данных. Удаление предыдущей версии из общего контейнера не должно удалять
текущую или создавать лишний снимок.

## What Changes

- Добавить отдельное подтверждение удаления выбранной старой версии в списке сохранений Яндекса.
- Уменьшать число восстановимых версий, сохраняя ID и байты текущей версии.
- Разделить logical seq и поколение физического контейнера v3; удалить previous без искусственного
  нового сохранения.
- Защищать последнюю независимую актуальную ветвь; удалять принятого старого клиента только с
  проверяемым подтверждением его принятия.
- Сохранять точный план операции до сети и повторять незавершённое удаление после проверки аккаунта
  и актуальности файлов.
- **BREAKING:** старый v2 клиент останавливается на контейнере v3 до любых облачных записей и
  требует обновления.

## Capabilities

### New Capabilities

- `yandex-manual-delete`: явное точечное удаление облачной истории с защитой текущих и параллельных
  данных.

### Modified Capabilities

Нет.

## Impact

Только Яндекс: контейнеры, reader/writer, журнал, координатор и карточки версий. Google, локальный
workspace и OAuth scopes не меняются. Реальные удаления в ходе разработки не выполняются.
