# Интеграция

- Основа `b24c818`, ветка `feat/history-depth-camera`, отдельный
  `artifacts/history-depth-camera-worktree`.
- Причина: depth входит в key камеры; переключение читало ранее сохранённый view выбранной глубины,
  заменяя текущие zoom/pan.
- Решение: depth-only переход переносит актуальный полный ChartView в обычный key нового depth до
  смены preferences. Ключи остаются `symbol:timeframe:engine:rangeDays`; миграция/новые произвольные
  ключи не нужны, старые backup читаются прежним способом.
- `copyDepthChartView` пишет обычную запись вида одной guarded IDB-транзакцией. Более поздняя
  транзакция импорта имеет приоритет; после commit контроллер повторно проверяет актуальность перед
  публикацией preferences. Shared-camera память переносом не изменяется.
- Owner/revision/UID/source/retired/persist/import guards исключают устаревшие адаптеры. Подписка
  запоминает краткую смену профиля или начало импорта во время ожидания, даже если флаги позже
  возвращаются в исходное состояние.
- Если canvas ещё не смонтирован, переносится текущий saved view после проверки контекста; если
  сохранённого вида нет, первоначальная инициализация остаётся без камеры и использует прежний fit.
  Retired/mismatched адаптер не разрешает fallback к хранилищу.
- Loader не переписан: он уже расширяет запрос до saved left edge и фактического MTP-прогрева.
  Перенесённый view теперь одинаково читают loader и lifecycle, поэтому depth=5 не ограничивает
  текущую видимую область пятью днями.
- Footer блокируется во время загрузки/импорта и сообщает ошибку записи вместо необработанного
  Promise rejection.
- Проверки: `pnpm check` — 230/230, `pnpm spec:validate` — 12/12, `git diff --check` чистый. Восемь
  новых тестов используют реальные controller/storage/history: оба engine contexts, 365→5→365→5
  после новых zoom/pan, reload, независимость другого инструмента, MTP440, backup keys,
  owner/UID/import/revision/retired гонки, отсутствие canvas и отказ commit. Существующие
  lifecycle/import/сохранение source tests проходят.
- Controller 488 строк после извлечения существующего saveView в controller-camera;
  production-модули короче 500 строк. Нативные адаптеры, fit, схема backup и loader не изменены.
- Ограничение прежнего persisted ChartView: он хранит горизонтальную камеру
  (barSpace/rightOffset/anchor/from/to), без ручного вертикального price range. Новых полей оси Y
  это исправление не вводит.
- Канонический проект, обслуживаемая сборка, профиль пользователя и сервер 5210 не изменялись;
  публикация не выполнялась. Визуальная проверка 365↔5 после wheel/pan и reload в обоих движках
  остаётся координатору на назначенном QA-профиле.
