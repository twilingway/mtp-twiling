# Design

## Context

Ключ вида включает rangeDays. setPreferences сохраняет исходный view, затем новый canvas и loader
читают другой depth-key, иногда содержащий старую камеру. Loader уже планирует левую границу полного
saved view и фактический прогрев.

## Goals / Non-Goals

**Goals:** точный перенос full view до переключения глубины с одинаковым чтением у loader и canvas.

**Non-Goals:** смена схемы ключей, переписывание старых backup, изменение нативных масштабов и fit,
удаление исторических данных.

## Decisions

- Сохранить существующие ключи `symbol:timeframe:engine:rangeDays`. При depth-only переходе заменить
  только вид нового depth текущим outgoing view. Миграция на новые ключи потребовала бы
  неоднозначного выбора старого view и изменила бы формат backup.
- Записать полный view одной guarded IDB-транзакцией без обновления общей shared-camera памяти.
  Контроллер ждёт commit перед сменой preferences. Запись создаёт только обычный существующий формат
  ключа, поэтому reload и manual backup работают без новой схемы.
- Проверять owner, revision, выбранный UID, source, persist/retired и import barrier. Временная
  подписка запоминает даже краткую смену owner или начало импорта между ожиданиями.
- Если canvas ещё не создан, переносить тот же saved view текущего depth, который прочёл бы canvas,
  с повторной проверкой после чтения. При отсутствии saved view сохранять первоначальный fit.
  Наличие устаревшего/retired адаптера не разрешает fallback.
- Транзакция записи создаётся синхронно после проверки; более поздняя транзакция импорта идёт после
  неё в IndexedDB и имеет приоритет. После ожидания commit guards проверяются повторно перед
  публикацией preferences.
- Вынести существующее сохранение камеры из почти 500-строчного controller в маленький модуль без
  изменения его прежних guard-правил.

## Risks / Trade-offs

- Начальная камера ещё не готова → переход не переносит частичный view; footer недоступен во время
  загрузки/импорта.
- Сохранённые keys по-прежнему различаются depth → каждый следующий depth-only переход явно
  обновляет целевой key актуальным view.
- Проверка реального native масштаба требует отдельного браузерного smoke координатора после
  интеграции.
