# Design

## Context

См. proposal.md. Реальный профиль Android DEV 0.3.44: 15083 свечи LKOH 30m, DPR 2,75, 229 видимых
баров, шаг 1,015; MTP on pan/Y p95 33,4 ms, off 50/16,8 ms. Fit on/off около 50 ms: основной поток
свечей/объёмов остаётся отдельным узким местом. GPU отдельно не измерен.

## Goals / Non-Goals

Ускорить повторную отрисовку тяжёлых линий и убрать работу выключенного MTP. Изменение не обещает
исправить общий FPS Fit или первоначальную растеризацию; физический повторный замер проводит
координатор.

## Decisions

- Источник SMA — исходный Candle.close; prefix и все 151 период неизменны. lightweight.ts и kline.ts
  передают исходные свечи. update продолжает увеличивать revision даже при том же close;
  resetRevision сохраняет принудительную инвалидизацию истории. Revision no-op оптимизация не входит
  в изменение, потому что массив и последний бар могут мутировать.
- Существующий dense путь сохраняется. Обычный шаг разрешён при >=30 периодах и >=8192 потенциальных
  видимых вершинах, с положительным конечным шагом. Это дешёвая верхняя оценка, а не новая выборка
  данных.
- Для нового пути с шагом выборки 1 захватить дополнительные реальные бары в горизонтальном padding,
  сохранив вызов каждой линии и каждый исходный vertex. Если расширение изменило бы прежнюю фазу
  выборки, оставить исходный диапазон. Dense sampling не менять.
- Горизонтальный padding обычного пути нацелен на один экран с каждой стороны. Сначала сохраняется
  прежний бюджетный Y reserve (до 20% экрана с каждой стороны), затем оставшийся лимит выделяется X.
  Для 808x1848 при DPR 2,75 поверхность 1620x2586 даёт приблизительно половину экрана по X с каждой
  стороны. Лимиты 4M pixels/16 MiB/4096 px не меняются; диапазон захвата ограничен шагом выборки 1.
- Экстремумы ordinary захвата читаются только между фактическими capture indices. SMA по-прежнему
  использует полный prefix и до 640 прошлых свечей; исторические данные не обрезаются. Dense
  сохраняет существующий domain и sampling phase.
- Проверка required logical indices выполняется до любого раннего вывода о пустом ценовом покрытии:
  локальный domain не доказывает отсутствие линий в ещё не захваченном viewport.
- Расширенный захват использовать только при преобразованном preview. Первый кадр и любой
  установившийся кадр вызывают нативный draw исходного диапазона: даже необычно толстые joins
  дополнительных offscreen сегментов не изменяют окончательные пиксели. Захват остаётся для
  следующего жеста. Обычный первый кадр требует захвата и нативного draw; холодное ускорение не
  заявляется.
- После жеста covered ordinary растр сохраняется, а точный кадр рисуется нативно. Повторное
  выделение поверхности требуется при выходе за захваченное покрытие либо прежней инвалидации
  данных, стилей, масштаба/DPR и несовместимой проекции; один лишь settled таймер не пересоздаёт
  покрытый слой.
- Три целочисленных X и три Y, linear modes 0/2/3, styles, данные, DPR и покрытие остаются
  обязательными. 4096 px на сторону, 4M pixels/16 MiB, единственная surface сохраняются.
- periods=[] завершает primitive draw/autoscale, model draw/extrema и raster до проекций,
  сканирования и canvas. Prefix/reset/update сохраняются для корректного повторного включения.

## Risks / Trade-offs

- Preview временно трансформирует изображение → после 180 ms и окончания ввода точный reraster.
- Сдвиг за padding → немедленный промах и точный новый захват; незахваченные края не показывать.
- Расширенный диапазон может добавить offscreen joins → проверять совпадение исходных сегментов
  внутри кадра и пиксельный результат отдельно, без заявления о проверке GPU по CPU benchmark.
