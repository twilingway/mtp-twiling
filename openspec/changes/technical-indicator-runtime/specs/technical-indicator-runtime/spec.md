# Spec Delta

## Purpose

Давать двум движкам общие проверяемые численные серии технических индикаторов и безопасные
определения нескольких независимых экземпляров.

## ADDED Requirements

### Requirement: Настоящие выровненные расчёты

Ядро SHALL рассчитывать RSI/Wilder RMA, MACD 12/26/9, Bollinger 20/2 с population variance, ATR14 и
Stochastic14/3/3 с общими SMA/EMA. Каждая серия SHALL сохранять длину и timestamps входа;
неизвестные и неопределённые значения SHALL быть null, без вымышленных свечей и NaN.

#### Scenario: Начало истории и пропуск

- **WHEN** истории недостаточно для seed либо поле бара отсутствует
- **THEN** выход содержит null на неподтверждённых местах, state MA не получает нулевые подстановки

#### Scenario: Последняя свеча исправлена

- **WHEN** вызывающий код повторяет расчёт после исправления OHLCV
- **THEN** результат определяется новым полным входом без мутации предыдущего входа или скрытого
  общего состояния

### Requirement: Документированные правила формул

Ядро SHALL использовать first-value seed EMA, SMA seed Wilder RMA, явные zero-loss/flat правила
встроенного RSI и документированные источники формул. Неоднозначное поведение gap renderer SHALL
быть явно отделено от математического игнорирования na.

#### Scenario: Полностью плоский RSI

- **WHEN** накоплено достаточно нулевых изменений для seed
- **THEN** RSI равен 100 по порядку zero-loss ветвей опубликованного built-in RSI

### Requirement: Сериализуемые независимые экземпляры

Определения и экземпляры SHALL состоять только из данных с проверяемыми ID, параметрами, pane,
видимостью и порядком. Несколько экземпляров одного определения SHALL иметь независимые параметры и
результаты. Неизвестные поля, ID и исполняемый код SHALL отклоняться.

#### Scenario: Два RSI

- **WHEN** создаются RSI14 и RSI7 с разными instance ID
- **THEN** оба корректно сериализуются и рассчитываются независимо

### Requirement: Честная недоступность

Пункт, требующий breadth, фундаментальных или внешних данных, SHALL иметь недоступный статус с
причиной. Он SHALL не возвращать фиктивные точки из одной OHLCV серии.

#### Scenario: Недостаточный набор данных

- **WHEN** запрошено определение без реализованного OHLCV расчёта
- **THEN** выполнение отклоняется с явной причиной, вместо пустой успешной серии
