## ADDED Requirements

### Requirement: Динамика использует собственную дневную историю каждого инструмента

Терминал SHALL показывать процент изменения относительно исторического дневного закрытия для каждого
выбранного инструмента и периода.

#### Scenario: У инструмента пропущена торговая дата

- **WHEN** опорный момент приходится на выходной, а раньше есть дневное закрытие
- **THEN** таблица использует это закрытие и показывает дату его свечи

#### Scenario: Не хватает истории или тикер неоднозначен

- **WHEN** инструмент не разрешился однозначно или до даты базы нет свечи с ненулевым закрытием
- **THEN** ячейка остаётся пустой и не получает вымышленный процент

### Requirement: Сезонная статистика использует только завершённые месяцы

Сезонный анализ SHALL показывать помесячные изменения, выборочную статистику и области проекции,
полученные из цен закрытия выбранного инструмента.

#### Scenario: Текущий месяц ещё торгуется

- **WHEN** поставщик вернул открытый месячный бар с текущей ценой
- **THEN** его изменение видно в таблице, а вклад в статистику появится после завершения месяца

#### Scenario: Проекция не использует результат будущего месяца

- **WHEN** есть несколько прошлых наблюдений того же календарного месяца
- **THEN** область рассчитывается из предыдущего закрытия и среднего, известного на момент открытия

### Requirement: Дополнительная история сохраняет текущую подписку и область графика

Загрузка для календарных индикаторов SHALL работать через существующий источник инструмента,
сохранять поток текущего графика и игнорировать ответы устаревшего аккаунта или набора параметров.

#### Scenario: Пользователь переключил инструмент до ответа

- **WHEN** загрузка ещё продолжается, а пользователь открывает другой инструмент
- **THEN** данные прежнего инструмента не появляются в сезонной таблице нового
