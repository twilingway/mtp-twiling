# Design

## Context

Расчётные модули знают календарные опорные даты и сезонные проекции. Локальный клиент уже хранит
свечи по поставщику, инструменту и интервалу. Адаптеры умеют рисовать ценовые прямоугольники.

## Decisions

- Использовать дневные свечи для динамики и месячные свечи для сезонности. Точное соответствие
  инструмента определяется идентификатором, поставщиком или однозначным тикером в котировках.
  Одновременные запросы ограничены. При смене аккаунта и настроек старые запросы отменяются.
- Для периода месяца использовать календарь биржи, известный по метаданным. Если биржа неизвестна,
  месячные расчёты не получают вымышленную зону. Незавершённый месяц виден в таблице без учёта в
  статистических оценках. Исторические свечи с флагом неподтверждённого закрытия пропускаются.
- Таблицы хранятся отдельно от числовых рядов и доступны с клавиатуры. Ячейки показывают знак и
  значение. Даты базы и пояснения к неполным данным доступны в раскрываемой таблице.
- Область сезонной проекции берёт среднее на начало месяца и ограничивается свечами этого месяца,
  которые есть у выбранного графика. Пустой месяц не рисуется.

## Risks / Trade-offs

- Пользователь добавляет сравниваемые инструменты из списка котировок. Неоднозначный тикер можно
  уточнить префиксом источника.
- Индикаторы показывают доступную историю. При отсутствующей базе или неподдерживаемом календаре в
  соответствующей части таблицы остаются пропуски с объяснением.
