# Design

## Context

YandexJournal принадлежит IndexedDB origin, а TerminalController и revision принадлежат окну.
Обычный export предварительно записывает preferences из интерфейса. Поэтому проверять общую базу
необходимо до capture.

## Goals / Non-Goals

Цель: исключить обратную отправку старого окна и сохранить реальные параллельные правки. За
пределами: изменение неизвестных heads, облачного формата и авторизации.

## Decisions

Координатор хранит принятую ассоциацию и revision своего окна. Изменение общей ассоциации при
неизменённой revision запускает guarded восстановление интерфейса из уже записанных локальных данных
до capture. Восстановление использует существующий native-restore без повторной записи backup. Если
окно изменено, transfer использует собственную базу окна и требует сравнения. Совпавшие heads с
обновлённым служебным digest сохраняют прежний readback repair.

Ранняя readonly-транзакция сканирует только ключи vault и читает значения association текущего
public clientId, без чтения auth-записей, расшифровки или создания device ID. Этот снимок создаётся
вместе с координатором, до поздней авторизации. Иначе B могло бы принять новую общую P2 за базу
своего старого интерфейса P1. Восстановление окна очищает только его camera cache в памяти;
persisted camera другого окна остаётся целой.

## Risks / Trade-offs

Режим восстановления записывается отдельной служебной записью `workspace-restore-recovery:<owner>`
до первого camera действия. Shared refresh заранее запрещает persistence старого adapter. Retry без
аргумента, включая новую инстанцию контроллера, берёт owner-scoped режим из журнала; обычный импорт
явно задаёт import. Успешное восстановление условно удаляет только свою operationId, поэтому более
новая операция и другой owner не затрагиваются. Это временный receipt операции, а не
пользовательская настройка.

Native ordinary import записывает replacement receipt в той же IDB-транзакции, что layout, views,
drawings и images. Внутренний options receipt связывает logical owner, operationId/nativeImportId и
physical storageOwner; эти поля не входят в backup. Commit публикует данные и mode import вместе,
abort сохраняет прежний receipt shared runtime. После commit controller только читает durable mode,
поэтому onCommitted/guard/квота отдельной записи не могут оставить устаревший shared mode. Пока
pending import не завершён, новый shared refresh не заменяет его режим сохранением камеры.

- Обрыв восстановления → capture не запускается; повтор повторяет только локальное восстановление.
- Новое окно без принятой базы → прежний явный выбор; автоматического принятия неизвестной истории
  нет.
- Разные профили браузера имеют разные IndexedDB → это отдельные клиенты; причина реального телефона
  требует отдельной проверки metadata.
