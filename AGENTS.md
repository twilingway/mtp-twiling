# Личный терминал — правила проекта

## Продукт и границы

- Отвечать пользователю коротко и по-русски. Идентификаторы и комментарии кода — на английском.
- React + TypeScript strict; два графика Lightweight Charts и KLineChart с общими данными и разметкой.
- Приложение — клиентская PWA. Сервер раздаёт только оболочку и обновления. Токен, REST/WS и IndexedDB принадлежат устройству пользователя; сервер не получает ключи и котировки.
- Никогда не печатать токены, не добавлять `.env`, `.secrets`, приватные профили и browser artifacts в Git/релиз.
- Только реальные данные. Пустые цены не подменять демонстрационными. Торговые операции/портфель не входят в задачу.
- Не менять соседние проекты, их процессы, порты и ветки. Локальный терминал: 5210; существующий стенд пользователя piano5190 не трогать.

## Разработка

- Общие правила перенесены из Piano Trainer и SpaceShip Defender по прямому указанию пользователя. См. `docs/CONFIG_SOURCES.md` и `docs/CODE_STYLE.md`.
- pnpm, ESLint + Prettier. Строгие типы, `allowJs:false`; не скрывать миграционные ошибки через `@ts-nocheck`, ослабление `strict` или массовый `any`.
- Чистая математика свечей, MTP и рисунков отделена от React/DOM/сети/часов. React владеет оболочкой/окнами; chart adapters владеют canvas.
- `App.tsx` только компонует интерфейс. Production-модули до500строк либо документированная причина разделения позже.
- Текущие пользовательские данные/ключи сохранять при миграциях. Импорт проверять до записи, ключ не экспортировать.
- UTF-8 без BOM; кириллицу передавать файлами, а не через потенциально неверную кодировку PowerShell pipe.
- Для архитектуры/функциональных изменений применять `.agents/skills/openspec-workflow/SKILL.md`, сценарии наблюдаемы и проверяемы. Прямые исправления небольшого UI допускаются без отдельной спецификации.
- Уже запрошенные React/TypeScript, PWA, индивидуальный ключ и VPS-размещение авторизованы пользователем; повторно подтверждать их не нужно.

## Делегирование

- Делегировать независимое исследование, спецификацию, реализацию и ревью, когда это сокращает путь к проверенному результату.
- Для крупной миграции использовать ограниченного `spec_architect`; перед завершением — независимого `reviewer`.
- Не назначать нескольким пишущим агентам одни файлы. Передавать конкретные пути, ограничения и проверки.
