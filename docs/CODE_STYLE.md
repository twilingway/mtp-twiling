# Стиль кода терминала

Основа: правила `games/towerdefander/docs/CODE_STYLE.md` и Piano Trainer.

- `src/App.tsx` — только композиция, ориентир80строк; страницы и окна — `src/screens/`, компоненты
  второго потребителя — `src/components/`.
- `src/model/` — чистые данные/математика и типы; `src/services/` — банк и IndexedDB; `src/charts/`
  — конкретные библиотеки; `src/screens/terminal/` — управление терминалом.
- Production-файлы максимум500строк. Длинные контроллеры делить по владению: история, профиль,
  каталог, рисунки, окна.
- TypeScript strict, типы импортируются через `import type`. Непроверенные внешние данные входят как
  unknown, затем проверяются/нормализуются. Не использовать `any` как способ завершить миграцию.
- Свечи, UID/таймфрейм, диапазоны, сохранённые настройки и резервные копии имеют общие типы.
- React перерисовывает только затронутые панели/цифры. Canvas обновляется по подписке, не
  пересоздаётся на каждый тик.
- Сначала узкая проверка изменения, затем typecheck/lint/format/test/build и релевантный browser
  smoke. Не создавать тесты, повторяющие реализацию без проверки поведения.
- Файлы UTF-8 без BOM, формат Prettier, линтер ESLint. Комментарии и имена в коде по-английски;
  интерфейс и продуктовые документы по-русски.
- Локализацию интерфейса вводить через общий каталог; миграция уже написанных русских строк
  фиксируется отдельным пунктом, не подменяет завершение текущей миграции типов.

Временное исключение после интеграции облаков `70a2c6e`: `device-slot-model.ts` (506 строк) и
`device-slot-provider.ts` (514 строк). В первом пока вместе находятся проверка причинности и
планирование CAS, во втором — единая lifecycle/credential-generation граница. Разделение отложено до
живой проверки CAS/миграции, чтобы не менять проверяемую границу в ходе приёмки. Следующее
расширение этих модулей должно предварительно вынести чистый планировщик и операции провайдера.

`src/charts/lightweight.ts` временно занимает 502 строки (501 до оптимизации свечей). Единственная
добавленная операция освобождает bridge в существующем destroy; следующий перенос lifecycle адаптера
должен вынести его целиком, сохраняя проверенный порядок отключения подписок.
