# Быстрая локальная проверка

Работайте в ветке задачи. Для проверки интерфейса на desktop и телефоне не нужны merge в `main`,
публикация и полная сборка после каждой правки.

```powershell
pnpm.cmd dev
# Если 5210 уже занят вашим другим стендом:
pnpm.cmd dev --port 5288
```

Откройте `http://127.0.0.1:5210/__dev/app/` (либо порт 5288). Корень сервера перенаправляет на этот
адрес. Сервер слушает только loopback, остаётся в управляемой сессии и останавливается через Ctrl+C.
Запускать второй сервер на занятом порту не требуется.

Изменения импортируемых TS/TSX и CSS пересобираются через incremental esbuild; изменения статических
CSS/HTML подхватываются автоматически. После успешного изменения страница перезагружается целиком.
Это не HMR: несохранённое состояние React теряется, сохранённые настройки и IndexedDB остаются. При
ошибке компиляции остаётся последняя успешная версия; сообщение видно в терминале и консоли
браузера.

Для подключённого по USB Android при настроенном `adb`:

```powershell
adb reverse tcp:5288 tcp:5288
```

Откройте в Chrome телефона `http://127.0.0.1:5288/__dev/app/`. Desktop и телефон используют свои
локальные данные и ключи. Команда `adb reverse --remove tcp:5288` убирает только это
перенаправление. Проверка телефона требует реально подключённого устройства; desktop viewport её не
заменяет.

Сервер создаёт файлы только в игнорируемом `artifacts/dev-runtime`. Общий с production конфиг
обеспечивает app, MTP, history codec, остальные model entries, install entry и лицензии библиотек.
Существующие статические vendor JS также доступны, если подготовлены обычным механизмом проекта;
основной клиент использует зависимости внутри bundle.

Dev использует отдельный путь, виртуальные version constants и отключает регистрацию service worker.
При первом открытии снимает регистрации service worker текущего origin и при наличии старого
controller делает одну перезагрузку. Кеши, IndexedDB и ключи не удаляются. Для проверки установки
PWA, offline и production updates нужен обычный production build и отдельный профиль/порт.

Каждая правка проходит только подходящую узкую проверку, например:

```powershell
node --test test/dev-server.test.mjs
```

`dev` не запускает typecheck, lint, тесты, production build или deploy. Полный `pnpm.cmd check` и
`pnpm.cmd spec:validate` остаются финальным шлюзом перед PR/релизом по правилам проекта, а не частью
каждого локального просмотра.

Справка без запуска сервера: `node scripts/dev.mjs --help`.
