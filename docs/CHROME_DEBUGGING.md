# Подключение к пользовательскому Chrome

Пользовательский браузер и отдельный тестовый профиль — разные границы. Для пользовательского Chrome
использовать существующее разрешённое подключение raw CDP без эмуляции устройства, viewport или
media features. Сохранять исходный инструмент, интервал и камеру перед замером.

27.11.2026 обнаружен побочный эффект Playwright `connectOverCDP`: установленная версия
`1.64.0-alpha` назначает `prefers-color-scheme: light`, когда ни страница, ни контекст явно не
задают схему. Это затронуло существующие вкладки пользователя, хотя тема самого Chrome была тёмной.
Само отсутствие вызова `page.emulateMedia` не доказывает отсутствие эмуляции.

После отключения Playwright выполнен raw CDP `Emulation.setEmulatedMedia` с `media: ""` и
`features: []` для затронутых страниц. 25 из 26 вкладок подтвердили возврат тёмной схемы; на одной
вкладке МТП сброс принят, но проверка `Runtime.evaluate` завершилась по таймауту. Вкладки и браузер
сохранены. Доказательства находятся в ignored каталоге `artifacts/mtp-chrome-media-cleanup`.

Не подключать Playwright повторно к пользовательскому браузеру после очистки. Для обычных визуальных
проверок допустим отдельный тестовый профиль Playwright; его настройки не должны применяться к
браузеру пользователя. Светлая и тёмная темы приложения проверяются внутри этого изолированного
профиля.

Для каждой текущей сессии браузера назначать одного владельца постоянного raw CDP соединения.
Остальные исполнители передают ему проверки; не создают собственные подключения. Новые вкладки и
attach выполняются через тот же WebSocket. Перезапуск одноразового скрипта снова вызывает системный
запрос Chrome и не заменяет удержание соединения.

До подключения к Chrome проверить управление helper на локальном mock: команды, статус, продление
lease и завершение должны работать без открытия нового WebSocket. Использовать устойчивую очередь
команд; недоступный stdin не обходить циклом reconnect. При разрыве сообщить координатору и не
переподключаться автоматически. Разрешение пользователя на сессию сохраняется, но системный запрос
самого Chrome при новом соединении скрипт подавить не может.
