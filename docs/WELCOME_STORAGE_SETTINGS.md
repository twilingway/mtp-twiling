# Приветствие и история устройства

## Поведение

При первом готовом запуске `WelcomeGate` открывает приветствие до банковского входа. Другое открытое
окно не перекрывается. Чекбокс «Больше не показывать на этом устройстве» записывается в IndexedDB
`preferences/device:welcome-v1` без owner/viewKey. Поэтому он действует для устройства, доступен до
логина и не попадает в layout/watchlist/views portable backup или Drive-снимок. Переключение
банковского профиля не сбрасывает скрытие.

Закрытие без чекбокса пропускает приветствие до следующей загрузки. Ошибка чтения не скрывает
информацию. Ошибка записи явно показана: есть повтор и продолжение без сохранения. Ручное открытие
доступно через «Аккаунт и настройки → Помощь и первый запуск» даже после скрытия. Ручное снятие
чекбокса вновь включает автоматический показ при последующей загрузке.

Текст RU/EN различает сервер оболочки/обновлений, локальный IndexedDB и личный Drive. Упомянуты
права API только для чтения, отсутствие сделок, переносимые настройки/индикаторы/рисунки/images,
локальная история и JSON backup. Есть privacy и публичный GitHub. Ссылка получения токена ведёт на
[официальную инструкцию Т‑Банка](https://developer.tbank.ru/invest/intro/intro/token), а настройки
банка — на <https://www.tbank.ru/invest/settings/>. Официальный источник проверен поиском
25.11.2026; доступ к банковскому аккаунту не выполнялся.

В аккаунте отдельные разделы «Подключение», «Google Диск», «История», «Импорт и экспорт». Drive и
ручной backup сохраняют прежние guards и поведение. Отдельный StoragePanel загружается только при
открытии «Истории», чтобы не сканировать IDB на каждом открытии настроек.

## Выборочная очистка

Показаны объём свечей, число свечей, инструментов и групп UID/interval. Общая оценка browser storage
отделена: она включает изображения и оболочку PWA и может быть недоступна. Таблица групп показывает
полный идентификатор, если инструмент уже удалён из watchlist.

Выбор изначально пустой. Кнопка строки выбирает конкретные UID/interval; «Все» выбирается явно.
Перед удалением показаны scope, объём, число свечей/групп и отдельная кнопка подтверждения.
Изменение scope отменяет старое подтверждение. После очистки статистика обновляется; новые свечи
могут записываться снова. Удаляется сохранённая история, открытый график может оставаться в памяти.

`HistorySettingsModel` проверяет owner/session и request epoch до/после async действий. Смена
профиля сбрасывает scope/preview; старый результат не публикуется новому профилю. Очистка во время
import/recovery/backup недоступна. Применение использует существующий `controller.clearHistory`: он
делает scoped clear только `history`/`coverage`. Рисунки, изображения, prefs, API vault и другие
владельцы не удаляются. Контроллер и сервис истории этой задачей не изменены.

Welcome/Account компонентов. Проверены device preference до логина, скрытие/повторное открытие,
ошибки load/save, точный scope/preview, обязательное подтверждение, owner/session races, поздние
ответы и реальные history-only storage операции с сохранением прочих stores/owners.

`3753d61c19daf5d9`, 291/291 тест. OpenSpec strict validation PASS 13/13. Модули до 500 непустых
строк.

Canonical/runtime/server/Google Cloud и браузерные профили не изменялись. SSR — структурная
проверка, визуальную не заменяет. Реальные Android/iOS, установка PWA, browser UI и скриншоты
остаются отдельной проверкой координатора после интеграции. Код IndexedDB общий, но browser
origin/профили/установленные приложения могут иметь отдельные хранилища; это не межбраузерный sync.
