# Карточка инструмента T-Invest

Карточка раскрывается после существующей котировки. Закрытая карточка не делает запросов. Каждый
раздел отдельно загружается при раскрытии; при закрытии, смене UID, профиля или импорте запрос
отменяется, устаревший результат не показывается. Ошибки имеют локальную кнопку повтора.

## Источники и значения

Контракты проверены 25 ноября 2026 года по официальным
[instruments.proto](https://github.com/RussianInvestments/investAPI/blob/main/src/docs/contracts/instruments.proto)
и
[marketdata.proto](https://github.com/RussianInvestments/investAPI/blob/main/src/docs/contracts/marketdata.proto).
Страницы [методов](https://developer.tbank.ru/invest/services/instruments/methods) и
[описания Instruments](https://developer.tbank.ru/invest/services/instruments/head-instruments) при
прямом открытии вернули 502/timeout. Содержимое методов прочитано через поисковый индекс
официального сайта; описание — через официальный
[head-instruments.md](https://github.com/RussianInvestments/investAPI/blob/main/src/docs/head-instruments.md).
Авторизованные ответы банка этим не проверены.

| Раздел              | Только читающие методы                 | Значение                                                                                                                                                          |
| ------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Основные показатели | GetInstrumentBy → GetAssetFundamentals | UID инструмента разрешается в assetUid. Снимок TTM/MRQ, не исторические отчёты. Валюта и фискальные даты из ответа. Дата обновления снимка методом не передаётся. |
| Дивиденды           | GetDividends                           | Сумма на бумагу, валюта, реестр, фактическая выплата, последний день покупки, тип выплаты. Фильтр по реестру: −2 года / +1 год.                                   |
| Календарь           | GetAssetReports                        | Дата публикации, год, номер и тип периода. −90 дней / +1 год. Ни выручки, ни EPS исторического отчёта этот метод не даёт.                                         |
| Прогнозы            | GetForecastBy                          | Инвестдом, дата рекомендации, целевая цена и валюта, консенсус и диапазон целей. Метод не передаёт дату и горизонт консенсуса.                                    |
| История             | GetCandles                             | Дневные свечи; объём в лотах. Актуальный proto допускает DAY до 6 лет / limit 2400; загрузчик использует более короткие окна.                                     |

Отсутствующие значения сохраняются как отсутствующие. Официальный head-instruments определяет
нулевые фундаментальные показатели как недоступные. Карточка показывает для них «—»; отрицательная
прибыль сохраняется. Значения без масштабирования, в валюте ответа; неподтверждённые множители
миллионов не применяются. EPS подписан на акцию. Денежный Quotation с явно переданным units=0 в
дивидендах остаётся нулём. Валюта «?» означает, что API её не передал.

Используется существующий браузерный TBankClient.request через публичный controller.sessionKey; ключ
не извлекается из клиента. Сервер, торговые методы, новые зависимости и запись свечей отсутствуют.
Кеш только в памяти, изолирован объектом сессии, максимум 40 записей. TTL показателей/справки — час,
остальных разделов — 15 минут. Совпадающие выполняющиеся запросы объединяются; последний ушедший
подписчик отменяет общий запрос. Ошибки не кешируются. Существующий transport сериализует HTTP,
ограничивает частоту и обрабатывает 429.

## Расчёты

- История сначала читается из существующего DAY IndexedDB и уже загруженного DAY графика только
  совпавшего UID. Их формат не хранит isComplete, поэтому последние два UTC дня исключены.
- При недостаточном покрытии раздел статистики делает один запрос за 380 дней — запас для начального
  закрытия годовой динамики. При достаточной старой истории делается один короткий запрос за 10 дней
  для проверки свежих завершённых свечей. Число API-confirmed и локальных unknown свечей показано
  раздельно; дата последнего включённого закрытия указана явно. Из REST включаются только
  isComplete=true, валидные OHLC и целочисленный неотрицательный объём. Текущий UTC день исключён из
  динамики/среднего объёма.
- Изменение за 1/3/6/12 месяцев: последнее закрытие / закрытие не позднее календарной целевой даты
  − 1. Начальное закрытие допускается максимум на 7 дней раньше цели. Последний день должен быть
  свежим в пределах 7 дней, внутренний разрыв более 14 дней делает результат недоступным.
- Средний объём: арифметическое среднее последних 30 доступных завершённых дневных сессий, в лотах.
  Требуется 30 наблюдений и тот же контроль свежести/разрывов.
- Сезонность запускается отдельной кнопкой. До шести последовательных годовых окон от 1 января
  текущего года минус 5 до сейчас; покрытые локальные окна переиспользуются. Есть прогресс и отмена.
- Доходность месяца: последнее закрытие месяца / последнее закрытие перед месяцем − 1. Требуются
  минимум 10 дневных свечей, начало в первые 7 дней, конец не ранее последних 7 дней месяца,
  предыдущее закрытие не старше 10 дней от начала и отсутствие внутренних разрывов более 14 дней.
  Текущий месяц исключён. Для среднего и доли положительных месяцев нужны минимум 3 наблюдения
  конкретного календарного месяца. N показан для каждого месяца, неполнота явно подписана.
- Это изменение цены без дивидендов и без самостоятельной корректировки сплитов. Проверка покрытия
  консервативная, не гарантирует наличие каждого торгового дня и не заменяет биржевой календарь.

## Проверки

В изолированном worktree от ffc41fe выполнены `pnpm check` (375/375 тестов, включая 11 новых),
`pnpm spec:validate` (21/21) и `git diff --check`. Sandbox блокировал запуск дочерних esbuild/Node
процессов с EPERM; полный check успешно повторён с разрешённым запуском этих процессов.

`node --test test/instrument-details.test.mjs` проверяет missing/zero, отрицательные результаты,
изоляцию UID/owner, ошибки/retry, дедупликацию и отмену последнего подписчика, локальную историю,
ограниченную последовательную загрузку, границы/неполноту расчётов и RU/EN HTML.

Browser QA для координатора в изолированном профиле, с тестовыми ответами без личного ключа:

1. Выбрать строку: закрытая карточка не отправляет HTTP. Раскрыть оболочку — запросов ещё нет.
2. Раскрыть показатели акции, проверить snapshot, валюту, дату получения и «—» при пропусках.
3. Проверить пустые дивиденды/календарь/прогнозы, затем 403 и локальный повтор; котировки остаются.
4. Отложить ответ A, переключить UID B/профиль, вернуть A: данные A не появляются в B.
5. Раскрыть сезонность: до кнопки нет многолетних запросов; после кнопки прогресс, закрытие
   отменяет.
6. Проверить длинные суммы, dark/light, RU/EN, узкую панель и мобильный drawer. Карточка имеет
   собственный вертикальный scroll, не выталкивает список за пределы панели.

Авторизованные ответы реального аккаунта, доступность каждого поля для отдельных эмитентов и
визуальный browser QA этим unit-набором не подтверждаются.
